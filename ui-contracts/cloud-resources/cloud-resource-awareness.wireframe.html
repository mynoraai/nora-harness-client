Permission & safety branches

These are execution policies and recovery rules, not additional product journeys.
Permission

Auto-run

Allowed mutation executes once and settles directly to the same Tool receipt. No artificial approval frame is added.

Permission

Ask before running

The Tool Call pauses on its exact resource effects. Approve once, workspace allow, or Deny resolves that same call.

Permission

Never run

Policy blocks before mutation. The user can continue local work or change policy; no fake API progress appears.

Safety

Changed / conflict / unknown

Changed sources invalidate approval; stale premises conflict; unknown outcomes require read-only discovery before retry.

Recovery summary

4.1 / 4.2 / 4.3 Tool recovery

Keep confirmed resources visible. Continue from the failed stage; unknown outcomes pause duplicate mutation until reality is determined.

Device provisioning

Cloud created · local delivery failed

Keep the Device ID as a partial receipt. Never register blindly again; revoke/re-provision or delete the unused Device after discovery.

Physical verification

Flash or connection failed

The registered Device remains `Never connected`. Retry build/flash or inspect hardware without creating another Device identity.

Test Session

Turn already in progress

A `409 turn_in_progress` does not queue or duplicate the Turn. Preserve the active Session and retry only after current state is read.
