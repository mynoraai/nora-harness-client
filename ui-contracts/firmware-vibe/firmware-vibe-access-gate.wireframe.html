State language pills & copy
pills

Tool-call pills

◷ Running ✓ Completed ✕ Not Authorized
Running — firmware tool in progress. Completed — real result (green; guaranteed no refusal). Not Authorized — refused, signed out (red). In-app agent errors also show Failed for non-auth failures.
copy

Refusal wording — app vs terminal

In-app (card): “Sign in to use firmware tools … Sign in once — every firmware tool here and in your terminal is authorized automatically. → Sign in to NoraHarness”.
NOT_AUTHORIZED: firmware-vibe requires a NoraHarness API key. Run the hw_fw_login tool to sign in from your browser (no key pasting), or create a key on the NoraHarness dashboard.
Terminal gets the wording above (no app card). The app deliberately keeps its “managed / Sign in to NoraHarness” wording out of the shared credential so a terminal user never sees app-only phrasing.

6.2

Mid-session sign-in gap

Signed in mid-session, gateway only → still Not Authorized. Firmware access is prepared at app start / on opening an in-app agent, not on the sign-in event.
Recovery → restart the app or open an in-app Claude / Codex conversation (6.2.1) → Completed.
9.1

Service unreachable

✕ Not Authorized
If the NoraHarness service can't be reached, the tool fails closed with an “unreachable” note. It never silently allows the tool to run.
Recovery → restore connectivity, retry (back to 2 → 3).
9.2

Access revoked

If the account's firmware access is revoked on the dashboard, a previously working tool returns to Not Authorized on its next call.
Recovery → restore access / re-issue credential, then 5 → 6 → 3.
