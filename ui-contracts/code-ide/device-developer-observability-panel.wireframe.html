Engineering readiness — acquisition cost & transport

🟢 wired — frame carries it today 🟡 measured — add to state.update 🔴 new — counter/timer
CAPABILITY-GATED RENDER
Core blocks (Memory · CPU · Stack · Connectivity/Power/OTA) always render. Voice ⟂ voice+harness · Audio ⟂ mic/speaker · render-FPS ⟂ display · camera ⟂ camera. Source = the same capability manifest the Device Manifest panel uses.
TWO TRANSPORT PATHS
firmware state.update{metrics}→harness updateDeviceState→<obsRoot>/<id>/metrics.json→ObservabilityStore→DeviceTab (global)
Path A · resources/health. metrics{} is written whole to a per-device log (overwrite); the app reads the log dir, not the active workspace. Discovery = list the dir. adr/126.
voice-loop-timing sink→<obsRoot>/<id>/voice-timing.jsonl→ObservabilityStore→waterfall
Path B · voice timing. The production sink appends each turn's stage records to the device's log — durable, survives the panel being closed (the event stream can't be re-pulled). adr/126.
MASTER SWITCH (adr/138)
One global runtime switch HH_OBS, default OFF — the toggle in the device-management header. OFF stops the whole subsystem in one place (host serial reader + WS state.update metric persistence + the full metrics pull + the 5 s RTT ping); the device is left at firmware baseline, the serial port is free, and device online/offline, control, and voice are untouched (they ride the same WS connection but a different code path). ON = serial-first, WS fallback: read the device serial fast lane if the port is readable, else the WS frame — the gateway arbitrates by frame freshness, so the UI shows no transport/source readout, just on/off. Runtime switch, not a reflash; the firmware compile gate HH_FEATURE_OBS_SERIAL is a separate, lower layer.
PER-METRIC GATING (when ON)
With observability ON, cheap metrics are always-on; expensive ones (per-core/per-task CPU, FPS, full task table) stay double-gated: compile-time GENERATE_RUN_TIME_STATS + runtime metrics.subscribe{level} — no cost when unobserved, no reflash.
P0 · light up what's wired
Overview strip + harness local/cloud + heap/RSSI/battery/OTA + uptime. Mostly 🟢.
P1 · voice waterfall
Path B sink → per-turn STT/LLM/TTS + p50/p95. Capability-gated.
P2 · full resource frame
SRAM/PSRAM/DMA detail, stack usage, record session, reconnects. 🟡.
P3 · new instrumentation
per-core/per-task CPU, FPS/frame, flash/NVS, I2S underrun, RTT. 🔴.
CPU caveat: per-core total is exact (each core's IDLE task); pinned tasks attribute exactly, unpinned tasks can't be split by ESP-IDF and are listed apart. Needs GENERATE_RUN_TIME_STATS — per-switch overhead + a sampling task — the one real device cost in P3 (accepted, see PM RESOLVED · CPU).

PM decisions

RESOLVED · namingConnection target is Application Harness (local / cloud), never "gateway". Local/cloud shown in the strip; it sets the voice-latency baseline.
RESOLVED · non-universal blocksVoice / Audio / render are capability-gated and hidden entirely when absent — driven by the device capability manifest.
RESOLVED · CPUPer-core load + per-task breakdown (not one aggregate). Accepts 🔴 runtime-stats cost. Stack shown as used/total bars.
PM DECISION · refresh cadenceResources piggyback the state.update interval; voice is per-turn. One combined refresh, or per-block?
PM DECISION · frame budgetstate.update has a max payload. Full metrics{} snapshot each interval, or deltas?
RESOLVED · multi-deviceA device-management header at the top (above the strip) opens a flat device list — the device is the entity; each row carries its harness as an attribute (kind · project [local] / install [cloud] · :port / channel · source). No grouping level (device → device, not device → project → device). Collapsible selector; pick a row → its dense panel below. Single device skips the picker; empty state with none. Devices come from the per-device log store across all harnesses — not just the open workspace. adr/126.
RESOLVED · observability master switch (adr/138)One global toggle in the device-management header, default OFF. OFF disables the entire subsystem at one gate (serial reader + WS metric persistence + full pull + RTT ping) — port free, device stays online, control/voice intact. ON = serial-first with WS fallback, arbitrated by the gateway; no source/transport readout in the UI, just on/off. Runtime switch (no reflash); separate from the firmware HH_FEATURE_OBS_SERIAL compile gate.
Decided answers fold into the Path-A / Path-B ADRs (PRD Downstream Design). Proposed wireframe — every value is sample telemetry, not live.
